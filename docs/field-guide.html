GoDaddy track · Best Use of ANS

CortexAi: agents that check each other's ID before they work together

A complete field guide to the project: what ANS is, what we're building, how every piece works, and how we ship it by Sunday morning. Read it top to bottom once; after that, use the contents to jump around.

01The project in one breath

A user gives CortexAi a goal, like "launch an online presence for Hokie Bites, a food truck in Blacksburg." Our Commander agent breaks it into jobs and hires specialist agents from other companies on the open web: a branding agent, a website builder, a compliance checker. Before hiring any of them, it uses GoDaddy's Agent Name Service (ANS) to prove each agent is who it claims to be, is still in good standing, and actually does the job. A live dashboard shows every identity check, every hire, every rejection, and a tamper-proof trail of who did what.

Why this wins the track

The track lead, Scott Courtney, said he cares about "agents talking to other agents across the open web." ANS is only meaningful when agents belong to different owners who have no reason to trust each other. Our whole project is built around that exact moment: a stranger agent asking to be trusted.

02Concepts you need first

You can't understand ANS without these. Each one gets a plain-English explanation.

AI agent
A program that uses an LLM (like Claude) to decide what to do, and can take actions: call APIs, write files, talk to other agents. In our project each agent is a small web server with an LLM "brain" and a specific job.
Domain name
A human-readable address you own, like webforge.xyz. Owning a domain is proof of identity on the internet: only the owner can change its settings.
DNS
The internet's phone book. You ask "where is webforge.xyz?" and DNS answers with an address. DNS can also hold small text notes (TXT records) — ANS uses these to publish facts about agents.
Public/private key pair
Two linked keys. The private key stays secret with its owner; the public key is shared with everyone. Anything signed with the private key can be checked with the public key. If the signature checks out, only the private-key holder could have made it.
Certificate
A digital ID card: "this public key belongs to this name," signed by a trusted issuer (a Certificate Authority, CA). The padlock in your browser is a certificate at work.
PKI
Public Key Infrastructure: the whole system of CAs, certificates and keys that lets strangers trust each other online.
CSR
Certificate Signing Request. You generate a key pair, then send the CA a CSR saying "please certify this public key for this name." You never send your private key.
ACME
The automated protocol for proving you control a domain (usually by adding a DNS record the CA asks for) and getting a certificate. It's how Let's Encrypt works, and ANS reuses it.
TLS / mTLS
TLS is the encryption behind HTTPS; normally only the server shows a certificate. mTLS (mutual TLS) means both sides show certificates, so both know who they're talking to. Ideal for agent-to-agent.
Transparency log
A public, append-only record. New entries can be added, but old ones can never be edited or deleted without everyone noticing. It uses a Merkle tree (a chain of hashes) to make tampering mathematically detectable.
Agent card
A JSON file an agent publishes describing itself: name, what it can do, how to call it. Like a business card for software.
MCP / A2A
Protocols for how agents talk. MCP (Anthropic) connects agents to tools; A2A (Google) connects agents to agents. ANS works with both — it handles identity, not the conversation itself.

03How ANS works

ANS = DNS + certificates + a public log, applied to AI agents instead of websites.

The analogy

Agents are employees. The ANS name is their name badge. The identity certificate is an ID card that can't be forged. DNS records are the company phone directory. The transparency log is an HR file of every hire and firing that nobody can quietly edit. The Registration Authority (run by GoDaddy) is HR, checking your papers before issuing a badge.

The ANS name

Every registered agent gets an official name anchored to a domain its owner controls. GoDaddy's published format packs protocol, agent, capability, owner and version into one name:

mcp://sentimentAnalyzer.textAnalysis.AcmeCorp.v1.0.example.com

GoDaddy's open-source reference implementation uses a shorter form:

ans://v1.0.0.my-agent.example.com

The spec is still evolving, so use whatever format the ANS API docs show. The key rule: the name, including its version, is permanent. Shipping v1.0.1 means a new name, retiring the old one, and a permanent log entry for both. That rule powers one of our demo scenarios.

The two certificates

CertificateWhat it provesUsed for
Server certificate (public)"This web address really is agent.webforge.xyz."Normal HTTPS to the agent's endpoint.
Identity certificate (private CA)"This key belongs to the agent with this exact ANS name."Agent-to-agent trust: mTLS, and signing messages and results.

The DNS records ANS publishes

These are examples from GoDaddy's design write-up; exact records may differ in the live API.

; where to find the agent card
_ans.sentiment       IN TXT   "url=https://sentiment.example.com/agent-card.json"
; how to connect (protocol, port)
_mcp._tcp.sentiment  IN HTTPS 1 . alpn=h2 port=443
; pin the expected certificate so an impostor cert is caught (DANE)
_443._tcp.sentiment  IN TLSA  3 1 1 [cert_hash]
; link to the Registration Authority's proof in the transparency log
_ra-badge.sentiment  IN TXT   "v=ra-badge1; url=https://transparency..."

The three ANS services

Registration Authority (RA)

Checks you control the domain, issues the identity certificate, publishes DNS records, and handles renewals and revocations.

Transparency log

Records every lifecycle event: registered, renewed, revoked. Gives out cryptographic receipts anyone can check.

Verifier

Checks those receipts, even offline. The open-source version ships a CLI called ans-verify.

ANS checks identity, not quality

ANS answers "is this really the Compliance agent, and is it still in good standing?" It does not answer "did the Compliance agent do a good job?" That second question is our own LLM logic. The project uses both, and in the pitch we should say clearly which is which.

06Flow: registering agents

Done once per agent, before the demo. We automate it with a script so we can re-run it.

  1. Buy the domainGet the organization's domain (for example webforge.xyz) and point a subdomain like agent.webforge.xyz at the hosted agent service.
  2. Generate a key pair and CSRThe agent's private key is created and kept by us, never uploaded. The CSR carries the public key and the requested ANS name. The SDKs do this for you; from Python it's a few lines with the cryptography library.
  3. Submit the registrationCall the ANS API with the ANS name, endpoint, agent card URL, capabilities, and CSR, authenticated with our GoDaddy API key.
  4. Prove domain controlThe RA asks us to publish a challenge (typically a DNS TXT record) on the domain. We add it; the RA checks it. This is the step most likely to eat time, so do it Friday night.
  5. Receive certificatesThe RA issues the identity certificate (and a server certificate if requested). We store it next to the private key in the agent's secrets.
  6. DNS records and log entry appearThe discovery records are published and the transparency log gets a "registered, verified" entry with a timestamp. The agent is now findable and verifiable by anyone.
Automate it

Write scripts/register_agents.py that loops over a config file of our five agents and runs steps 2–5. Then re-registering after a mistake takes one command instead of an hour.

07Flow: running a mission

What happens, in order, after the user types the mission and presses Launch.

  1. Mission arrivesThe dashboard sends the mission text to the Commander. The event hub logs mission.started.
  2. PlanThe Commander's LLM breaks it into jobs, each tagged with a required capability: brand.identity, then site.generate (needs the brand kit), then compliance.review.
  3. DiscoverFor each capability, the Commander finds candidate agents. Best case: a registry search by capability. Fallback: a list of known ANS names it resolves one by one. Ask Scott which the API supports.
  4. VerifyThe Trust Gate runs its five checks on each candidate. Every check result streams to the dashboard. Candidates that fail are rejected with a reason.
  5. Mutual checkWhen the Commander contacts a vendor, the vendor runs the same Trust Gate on the Commander. A vendor won't work for an unverified client. Trust goes both ways.
  6. Hire and workThe Commander sends the job. The vendor's LLM does the work.
  7. Signed deliveryThe vendor signs its result with its identity key. The Commander checks the signature before using it, so every artifact traces to a verified agent.
  8. Hand-offThe brand kit goes to the site builder; the site goes to compliance. Before each hand-off, the Commander re-checks the agent's status, which is what makes live revocation work.
  9. Review loopIf compliance flags a problem (say, no allergen disclaimer), the Commander sends it back to the site builder once, then re-reviews.
  10. DeliverThe dashboard shows the finished landing page plus a trust report: every agent involved, every check, every signature, with links to transparency log receipts.

08The Trust Gate

The five checks every agent runs before trusting another. This is where judges see ANS actually doing work.

#CheckQuestion it answersHowFails when
1ResolveDoes this agent exist in ANS?Look up the ANS name via the API or DNS; fetch the agent card.Unregistered name, lookalike domain.
2AuthenticateIs the thing I'm talking to the real holder of that identity?mTLS, or a signed challenge: send a random nonce, verify the signature with the public key in its identity certificate, and confirm the cert chains to the ANS CA and names this exact agent.Impostor copied the card but lacks the private key.
3StatusIs it still in good standing?Check the transparency log / registry status.Revoked or expired.
4CapabilityDoes it actually do this job?Compare the job's required capability to the agent card.A real agent hired for the wrong task.
5PolicyDoes it meet our rules?Our own rules, e.g. version pinned to 1.x, domain on allowlist, registered more than a day.Silent version change, brand-new registration.

Pseudocode. Function names like ans.resolve stand in for whatever the real API calls are.

# trustgate/gate.py — pseudocode
async def check_agent(ans_name, capability, policy):
    checks = {}

    # 1. Resolve: does it exist? what does it claim?
    record = await ans.resolve(ans_name)
    card = await fetch_json(record.agent_card_url) if record else None
    checks["resolve"] = record is not None

    # 2. Authenticate: prove it holds the private key
    nonce = secrets.token_hex(16)
    sig = await post(card["endpoint"] + "/challenge", {"nonce": nonce})
    cert = load_cert(record.identity_cert)
    checks["authenticate"] = (
        chains_to_ans_ca(cert)
        and cert_names(cert) == ans_name
        and verify_signature(cert.public_key(), nonce, sig)
    )

    # 3. Status: not revoked or expired
    checks["status"] = (await ans.status(ans_name)) == "ACTIVE"

    # 4. Capability: it does this job
    checks["capability"] = capability in card["capabilities"]

    # 5. Policy: our own rules
    checks["policy"] = policy.allows(record)

    verdict = "TRUSTED" if all(checks.values()) else "REJECTED"
    await emit("trust.check", subject=ans_name, verdict=verdict, checks=checks)
    return verdict
Make it visible

Emit an event for every individual check, not just the verdict. On the dashboard, five ticks lighting up one by one, or one turning red with a reason, is the moment judges will remember.

09Chaos scenarios

Buttons in the dashboard that break things on purpose, live, to prove ANS works.

rejected The impostor

The impostor copies the real Brand agent's public agent card and claims its ANS name. Checks 1, 3 and 4 pass, because it's pointing at real public data. Check 2 fails: it can't sign the nonce without the private key. The dashboard shows exactly which check caught it. This teaches the audience the core idea: public information can be copied, private keys can't.

revoked Live revocation

Mid-mission, click "Revoke" on the site builder. We call the ANS API to revoke it. Before the next hand-off the Commander re-checks status, check 3 fails, and it drops webforge.xyz, discovers sitesmith.xyz, verifies it, and carries on. The mission still finishes.

paused Silent upgrade

The compliance vendor ships v1.1 without telling anyone. Because the version is part of the ANS name, the name changes. Check 5 fails (our policy pins v1.0), and the Commander pauses with an "Approve new version?" prompt on the dashboard. A human clicks approve; the change is recorded in the log.

stretch Lookalike domain

An agent registers on brandstudi0.xyz (zero, not o). It passes identity checks, since it really owns that domain, but fails our allowlist policy. Shows that ANS makes identity certain, and policy decides whom to trust.

17What's real vs simulated

Judges respect honesty. Say this up front in the pitch.

real

  • ANS registrations, certificates, DNS records, log entries
  • Every identity check and signature
  • Revocation through the ANS API
  • LLM agents doing real work
  • Separate domains, separately hosted

simulated

  • The five "companies" are fictional and all built by us
  • The impostor is an attacker we wrote
  • Hokie Bites is a pretend customer

The line to use: "We simulated five independent organizations. ANS has no idea they share an author — to the protocol, they're strangers, and that's the point." If a real agent from GoDaddy's public registry is callable, hiring it live would remove the caveat entirely.
