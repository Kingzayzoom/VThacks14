Product spec · GoDaddy Best Use of ANS

Mission Control

Hire AI agents you can actually trust.

Mission Control turns a plain-English goal into finished work by hiring specialist AI agents from across the web. Before any agent touches the job, Mission Control proves who it is through GoDaddy's Agent Name Service. Every hire, every rejection and every deliverable is visible, signed and traceable.

Category
Multi-agent orchestration with built-in trust
Primary user
Small business owners and the developers who serve them
Core technology
GoDaddy ANS + Gemini-powered agents
Demo mission
Launch Hokie Bites, a Blacksburg food truck, online

The problem

AI agents are starting to hire other AI agents. Nothing tells them who they're dealing with.

Anyone can claim a name

An agent says "I'm BrandStudio's design agent." Today there's no standard way to check. Impersonation is as easy as copying a JSON file.

No accountability

When work passes through five agents, nobody can prove afterwards which agent produced which part, or whether it was altered on the way.

Silent changes

A vendor can swap the model or logic behind its agent overnight. The agent you vetted on Monday isn't necessarily the one you're using on Friday.

No off switch

When an agent is compromised, there's no shared way to tell everyone "stop trusting this one, now."

Who it's for

Mission owner

The small business owner

Runs a food truck, a salon, an Etsy shop. Wants results (a website, a menu, a marketing plan) without understanding AI internals.

I just want it done, and I don't want some random bot touching my business.

Builder

The developer or agency

Builds workflows that chain agents from multiple vendors. Needs verification, audit logs and failover without writing them from scratch.

I need to prove to my client exactly which agents touched their data.

Agent vendor

The company selling an agent

Offers a specialist agent (branding, legal review, translation). Wants to be discoverable and trusted by buyers.

How do customers know my agent is the real one and not a knock-off?

How it works

The whole product in four steps.

Describe

You type a goal in plain English. The Commander agent breaks it into jobs.

Find

For each job, Mission Control finds specialist agents through the ANS registry.

Verify

Each candidate must pass five identity checks before it's hired. Impostors are blocked.

Deliver

Agents do the work and sign it. You get the result plus a trust report proving where every piece came from.

States and rules

The labels the product uses everywhere. Agree on these so the dashboard, agents and pitch all say the same thing.

Mission lifecycle

Planning→ Hiring→ Working→ Reviewing→ Delivered

Any active state can move to Paused (waiting for owner approval) or Failed (no verified agent available for a job).

Agent trust states

Unchecked
Found but not yet verified. Can't be hired.
Verified
Passed all five checks. Can be hired.
Needs approval
Identity is fine, but it broke one of the owner's rules (e.g. new version). Waiting on a human.
Blocked
Failed an identity check. Never hired. Usually an impostor.
Revoked
Was verified, then revoked in ANS. Dropped immediately and replaced.

Rules the product always follows

  • No agent receives any work before passing all five checks.
  • Status is re-checked before every hand-off, not just at hiring.
  • Unsigned or wrongly signed results are thrown away, never shown.
  • A version change always counts as a new agent.
  • Private keys are never sent to the AI model or shown in the UI.

User journeys

1. The happy path

Mission owner · Hokie Bites

  1. Types "Launch an online presence for Hokie Bites, a food truck in Blacksburg" and presses Launch.
  2. Sees the plan appear: brand kit, landing page, compliance review.
  3. Watches three vendor agents get verified, each with five green checks.
  4. Gets a finished landing page in the Hokie Bites brand, plus a trust report. Time: about a minute.

2. The impostor

Attacker tries to take a job

  1. A fake agent copies BrandStudio's public agent card and claims its name.
  2. It passes the lookup checks, because the public information is real.
  3. Mission Control asks it to sign a random challenge. It can't, because it doesn't have BrandStudio's private key.
  4. It's blocked, and the feed says exactly why. The real BrandStudio agent gets the job.

3. The compromised vendor

Mission owner, mid-mission

  1. WebForge's site builder is revoked in ANS (in the demo, by pressing Revoke).
  2. Before the next hand-off, Mission Control re-checks status and sees "revoked."
  3. It drops WebForge, verifies the backup SiteSmith agent, and hands it the job.
  4. The mission finishes. The trust report records the switch. The owner didn't have to do anything.

4. The surprise upgrade

Mission owner gets a decision

  1. LegalCheck ships v1.1.0 of its compliance agent without notice.
  2. Because the version is part of the ANS name, Mission Control notices the change.
  3. The owner's policy pins v1.0.x, so the mission pauses and asks.
  4. The owner approves, or picks another agent. The decision is recorded.

The GoDaddy angle

Why this matters to the company judging it. Use one or two of these in the pitch.

Domains become agent identities

Every domain GoDaddy sells could anchor a verified agent. Mission Control shows the demand side: buyers who will only hire verified agents.

Small businesses, served by agents

GoDaddy's core customers are small businesses. Mission Control lets them use AI agents without having to judge which ones are trustworthy.

Vendors get a reason to register

If buyers like Mission Control only hire ANS-verified agents, every agent vendor has a reason to register, which grows the ANS ecosystem.

Under the hood

The short version. The engineering field guide has the full detail.

  • Agents: Python + FastAPI. One shared codebase; each agent differs only by prompt, skills and keys.
  • Agent brains: Gemini API (free tier) with JSON output. Each teammate uses their own key during development; one key is reserved for the demo.
  • Identity: GoDaddy ANS API for registration, lookup, status and revocation. Local fallback: GoDaddy's open-source ANS build.
  • Dashboard: Next.js + React, live updates over WebSocket from a small event hub.
  • Hosting: One service per agent on Render, Railway or Fly.io, each on its own domain.

Honest framing for judges: the five companies are fictional and built by the team. Every ANS registration, identity check, signature and revocation is real.
